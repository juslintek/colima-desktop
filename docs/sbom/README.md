# Software Bill of Materials & Vulnerability Report

Supply-chain artifacts for Colima Desktop (roadmap **R7** / Requirement **11.3**:
_"produce SBOMs and a vulnerability report containing zero known critical vulnerabilities"_).

This directory is a **committed** release artifact location (not the git-ignored
`artifacts/live/`). Everything here is regenerated by two reproducible scripts.

## Contents

| Path | What | Produced by |
|------|------|-------------|
| `cyclonedx/*.cdx.json` | CycloneDX 1.5 SBOM per component + an aggregate | `scripts/sbom.sh` |
| `components.md` | Human-readable component inventory (counts per ecosystem) | `scripts/sbom_gen.py` |
| `components.json` | Machine-readable component roll-up | `scripts/sbom_gen.py` |
| `VULNERABILITY-REPORT.md` | Severity-summarised, honest vulnerability report | `scripts/vuln_report.py` |
| `vuln-summary.json` | Machine-readable vulnerability roll-up + gate verdict | `scripts/vuln_report.py` |
| `scans/` | Raw per-ecosystem scanner output (the evidence behind the report) | native scanners |

## Components covered

Every shipped component's dependency graph is inventoried, straight from its committed manifest/lockfile:

| Component | Ecosystem | Source manifest | Vulnerability scanner |
|-----------|-----------|-----------------|-----------------------|
| `colima-daemon` | Go modules | `daemon/go.mod` | `govulncheck ./...` |
| `colima-tui` | Go modules | `tui/go.mod` | `govulncheck ./...` |

## Regenerating

```bash
make sbom             # SBOMs only (offline, byte-stable)
make security-scan    # SBOMs + run every available vulnerability scanner + report
make security-gate    # same, but exit non-zero on any CRITICAL finding (RC gate)
```

- **SBOMs are deterministic/offline**: `scripts/sbom_gen.py` reads the committed
  lockfiles and emits byte-stable CycloneDX 1.5 (no embedded timestamp/serial by
  default). If [`syft`](https://github.com/anchore/syft) is installed, `scripts/sbom.sh`
  uses it instead; otherwise the deterministic generator is the fallback.
- **The vulnerability report is a point-in-time scan** (advisory databases evolve),
  so re-run it before each release. Missing scanners are recorded honestly as
  "not run" with a reason rather than silently skipped.

## Release / RC-gate integration

`scripts/security-scan.sh --fail-on-critical` (a.k.a. `make security-gate`) exits
non-zero when any **critical** finding exists, satisfying Requirement 11.3's
"zero known critical vulnerabilities". The release-candidate CI gate (task 12.5,
`.github/workflows/security-scan.yml`) runs this and uploads `docs/sbom/` as a
release artifact. Lower-severity findings are reported for triage but do not
auto-block. The release pipeline (`release.yml`, task 13.1) attaches these SBOMs
to the versioned artifacts.
